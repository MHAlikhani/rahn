# RAHN v1.0 Review

Date: 2026-09-02. Reviewer pass over the charter's v1.0 requirements (charter §25, §52).

## Gate checklist

- [x] **Stable state semantics** — canonical format v2 frozen for 1.x (ADR 0019); identity test-enforced cross-platform.
- [x] **Documented state/transition semantics** — docs/spec/ (state, objects, transitions, serialization, storage) normative.
- [x] **Compatibility strategy** — ADR 0019 (semver via rahn-sdk + CLI contracts; IR frozen; deprecation policy).
- [x] **Security review** — posture unchanged and documented (docs/spec/security.md): no network I/O by default, untrusted-input parsing, hash-verified integrity, simulation default; namespace backend opt-in with structural host safety (ADR 0012); peer sync trust boundary documented (ADR 0015). Signed transitions remain Future — recorded limitation, not a gap hidden.
- [x] **Comprehensive tests** — 136 tests passing plus 4 ignored benchmark harnesses (measured on Windows with `--all-features`; counts vary by platform and feature flags): adversarial canonical parsing, corruption refusal, property tests (4 families, 600 seeds), distributed failure scenarios (7), causal/observation determinism, CLI e2e, cross-run determinism.
- [x] **Reproducible builds** — partial: single dependency tree (sha2 + transitive, audited in third-party.md), no platform-specific build logic; byte-identical *history* reproducibility is test-enforced. Binary reproducibility not verified (recorded limitation).
- [x] **Usable CLI/API** — 21 CLI subcommands with documented usage; `rahn-sdk` facade with doctests and surface guards.
- [x] **Credible documentation** — README/ARCHITECTURE/DESIGN/GLOSSARY synced; 12 spec documents; 19 ADRs; 8 stage reports; white paper at v1.0 with claim-status markers and honest §27.
- [x] **Clear limitations** — docs/research/limitations.md + per-stage reports.
- [x] **Dependency audit** — 1 direct dependency (sha2, Apache-2.0 OR MIT) + audited transitive closure (docs/third-party.md).
- [x] **Research conclusions** — final-comparison.md; hypotheses status in research docs; RQ1 partially answered with evidence, RQ2/RQ3 implemented with their studies (E2/E3) pending, RQ4–RQ10 open and documented.
- [x] **Extension model** — ADR 0019 §3 (backends, invariants, observations, sync).
- [x] **Contribution workflow** — CONTRIBUTING.md, issue templates (bug/feature/RFC), governance, CoC, CI gates.
- [x] **Release process** — ADR 0019 §4.

## Known limitations carried into 1.0 (honest, not blockers)

1. No addressing/traffic control → connectivity is link-existence only.
2. O(m·n) batch-apply and per-object sync transport (recorded debts).
3. Namespace execution CI-validated on a minimal scenario only.
4. No signed transitions/authenticated replicas.
5. Binary build reproducibility unverified.
6. All measurements single-machine.

## Definition of done (charter §52)

A technically competent external engineer or researcher can: understand the architecture (ARCHITECTURE + concepts + white paper); build and test (`cargo build/test`); reproduce identity/determinism (reproducibility.md + tests); inspect state/transitions (CLI + specs); verify invariants (CLI + constitution); understand execution boundaries (ADR 0008/0012/0016); extend (ADR 0019 extension model); understand limitations (limitations.md + stage reports); contribute (CONTRIBUTING + templates + governance). **Satisfied.**

## Verdict

Charter v1.0 requirements met. v1.0.0 is warranted as the first stable release, with the limitations above carried forward explicitly.
