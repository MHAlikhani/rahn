# Stage 4 Report — v0.4.0-alpha: Observability

Date: 2026-06-13. ADR: [0013](../../adr/0013-observation-model.md). Release: **v0.4.0-alpha**.

## Objective

Introduce Observation as a first-class concept: structured, deterministic, state-associated records with provenance — the substrate Stage 5 (causal memory) will consume. No dashboards, collectors, or causal semantics.

## Implementation changes

- **`rahn-state::obs`**: `Observation { seq, time_ns, subject, metric, value }`; `Subject` = `node/<id>` or `node/<id>/<iface>`; `Value` = `Counter(u64) | Gauge(i64) | Event(String)` (exact, float-free per ADR 0003). Canonical record encoding, strict total parse (unknown tags, trailing bytes, malformed UTF-8 → loud errors).
- **Ordering**: `(time_ns, seq)` ascending; timestamps are **caller-supplied** (`--at <unix-ns>`) — no implicit clocks, so identical command sequences produce byte-identical logs (test-enforced). `seq` is the deterministic ingest position.
- **Storage**: append-only, versioned-framed log (`.rahn/observations.log`) in `rahn-state::obs::log`; corruption (truncated frame, oversized frame, bad record) refused loudly; never silently repaired.
- **Provenance**: ingest validates the subject against the current HEAD state and records that state id in the record; unknown subjects are rejected.
- **CLI**: `rahn observe <subject> <metric> counter:..|gauge:..|event:.. --at <ns>`; `rahn observations [node-filter]` (deterministic TSV).

## Architectural changes

- The state model is unchanged (no canonical-format bump); observations are a separate immutable log associated with states by reference. This keeps RQ1's state-identity guarantees untouched while giving Stage 5 a durable event substrate.

## Experiments

- **E-obs (new): ingestion cost** — see benchmark results. Environment: Windows 11 (build 28000), i5-12450HX, 12 GB RAM, rustc 1.99.0-nightly, commit `54ee0f7`, release build, medians over 3–5 runs, 100 000 records over a 100-node ring.

## Benchmark results

| Metric | Result |
|---|---|
| Ingest (encode + append), 100k records | 25 783.8 ms median (~3 878 rec/s) |
| Single-append latency (median) | 144.0 µs |
| Full read + parse of 100k records | 68.3 ms |
| Log size | 15 652 969 bytes (≈156.5 B/record) |

Interpretation (scoped to this single-machine run):

- Read/parse is fast (0.68 µs/record); storage is compact for canonical framing.
- **Ingest is dominated by per-append file open+write+flush** (~144 µs each) — the honest v0.4 cost for CLI-shaped one-record-per-process ingestion. A batched/buffered writer would amortize this substantially and is recorded as known performance debt (parallel to the O(m·n) transition debt), not optimized in this stage.

## Tests

- Unit: record round-trip (all value kinds, i64::MIN gauge), adversarial parse (trailing bytes, unknown tags), metric/subject/event-bound validation, `(time_ns, seq)` ordering, subject association against a network.
- Log: round-trip, malformed-framing loudness (truncation test).
- E2E: ingest → filtered list → unknown-subject rejection → malformed value rejection → missing-`--at` usage rejection; **cross-run determinism** of the observation log bytes.
- Workspace: 109 tests green; fmt and clippy (`-D warnings`) clean.

## Limitations

- No units system (unit lives in the metric name by convention, e.g. `latency_ns`).
- No counter-monotonicity enforcement; no aggregation or downsampling; no retention/pruning policy.
- Clock authority is entirely the caller; no clock-sync or skew handling (recorded input, documented).
- Links are not yet addressable subjects (nodes/interfaces only) — addressing remains a Stage 2-scope deferral.
- Batched ingestion performance debt (above).

## Unresolved questions

- RQ5 (causal attribution fidelity) opens in Stage 5; these records are its inputs, nothing here asserts causality.
- Should link subjects and execution-observation hooks (`rahn apply --execute` recording plan results as events) join the log? Design for Stage 4.5 alongside addressing.

## Next-stage implications

- Stage 5 (causal memory) consumes this log plus commit records; `(time_ns, seq)` ordering and state provenance give every causal claim a checkable anchor.
