# Stage 5 Report — v0.5.0-alpha: Causal Memory

Date: 2026-06-26. ADR: [0014](../../adr/0014-causal-memory.md). Release: **v0.5.0-alpha**.

## Objective

Represent and query causal hypotheses tied to network state and observations **without overstating what the system proves** (charter Stage 5 gate). No causal inference.

## Implementation changes

- **`rahn-state::causal`**: `CausalEdge { seq, from: Anchor, to: Anchor, status, note }`; anchors are immutable records — `Observation(seq)` (positional, from the ADR 0013 log) or `Commit(id)` (content-addressed).
- **Epistemic statuses, structurally enforced:** `temporal-correlation` (ordering only), `hypothesis` (suspected link), `verified` — the last MAY only have Commit anchors on both ends (test-enforced); observation-anchored edges cannot be verified because no mechanism proves them.
- **DAG invariant:** insertion is rejected if it would close a cycle (deterministic DFS over the forward adjacency).
- **Anchor validation:** edges cannot dangle — observation seqs must exist in the log, commit ids in the store (checked at `relate` time).
- **Storage:** append-only `causal.log` with the same versioned framing and loud-corruption rules as observations.
- **Incident:** the connected component around an anchor — a query result, not a stored type (named incident records deferred).
- **CLI:** `rahn relate <anchor> <anchor> <status> --note <text>`; `rahn explain <anchor>` — output carries edge statuses verbatim and states that relations are asserted, not proven.

## Architectural changes

- Causality is a separate immutable log, never inferred and never embedded in observations or commits. The system creates no edges automatically — all edges are explicit assertions whose status labels their strength.

## Experiments

- **E-causal: graph operation cost** — 10 000-edge linear chain (worst case for cycle-check DFS depth). Environment: Windows 11, i5-12450HX, rustc 1.99.0-nightly, commit `a916be6`, release build, medians.

## Benchmark results

| Operation (10k-edge chain) | Result |
|---|---|
| Graph build from edges | 18.5 ms |
| Cycle check (full-chain DFS, deepest case) | 4.3 ms |
| Incident (connected component) | 5.7 ms |

Interpretation: a performance bug was found and fixed during this stage — the first incident implementation rescanned all edges per BFS step (O(V·E): 2 701.9 ms); adding a reverse adjacency map made it O(component) (5.7 ms, ~470× faster). Both numbers recorded honestly.

## Limitations

- Edges are human-asserted; the system validates structure (existence, DAG, status rules) but proves nothing about the world.
- Incidents are implicit (connected components); named incident records and `rahn explain <incident>` narratives are deferred.
- No automatic edge extraction from execution plans or transition diffs (candidate future feature).
- Ordering semantics across anchors of different kinds (obs vs commit) are the recorder's responsibility; no cross-log clock unification.

## Unresolved questions

- Can temporal-correlation edges be *derived* soundly from `(time_ns, seq)` data as a read-time suggestion (labeled as such)? Deferred — would be the first system-generated edges.
- RQ5 (attribution fidelity) remains open: with real telemetry, how trustworthy are hypothesis chains? Requires addressing + traffic (Stage 3 deferrals) to exercise meaningfully.
