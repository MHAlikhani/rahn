# Stage 2 Report — v0.2.0-alpha: Network Graph Foundation

Date: 2026-05-08. Commits: `bd35d6f` (ADR 0011), `36dd2de` (implementation), plus the release commit. Release: **v0.2.0-alpha** (tagged).

## Objective

Transform the v0.1 state engine into a meaningful network graph model: interfaces as first-class objects, deterministic graph queries with path discovery, isolation constraints, and scaling evidence — with no real network execution (charter Stage 2 gate).

## Implementation changes

- **Interface-endpoint model (ADR 0011):** `Interface` is a first-class object owned by nodes (unique name per node, metadata, part of identity/diff/merge/verification). Links connect `(node, interface)` endpoints, normalized, undirected. Links between two interfaces of the same node are prohibited (topological loop).
- **Canonical format v2:** nodes carry owned interfaces; links carry endpoint pairs; every v0.1 strictness property retained (total ordering, ambient-free, dangling-endpoint rejection, normalized endpoints, truncation/trailing-byte rejection). v1 bytes are rejected loudly with a pointer to the ADR; no silent migration (alpha-era data, explicitly decided).
- **Operation vocabulary extended:** `add_interface`, `remove_interface` (rejected while linked); `add_link`/`remove_link` address endpoints. All changes remain explicit recorded transitions.
- **Graph queries (`rahn-state::graph`):** `shortest_path` (BFS over sorted adjacency, lexicographic tie-break — deterministic equal-length route selection), `neighbors`, `reachable_from`, `components`, `adjacency`. All operate on the node graph induced by interface links.
- **Isolation constraints:** constitution gains `prohibit-connectivity a b`; connectivity semantics stay node-level (ADR 0011 decision 5).
- **CLI:** `rahn interface add/remove`; `rahn link add/remove a/eth0 b/eth0`; new `rahn path from to`; diff/state/inspect/log/apply output interface-aware.

## Architectural changes

- Canonical format version bump 1 → 2 (ADR 0011; identity of states changes relative to v0.1 — expected and documented).
- Diff semantics: added/removed nodes report their interfaces explicitly (a state delta is complete); execution plans subsume interface removals into node removals (operational dependency-safety), documented in `rahn-sim`.

## Research performed

- Prior-art position for interfaces/graph queries unchanged from docs/research/prior-art.md §2/§4 (inventory systems model interfaces relationally; RAHN's are identity-bearing and diff/merge-participating). No new novelty claims.

## Experiments

- **E2 (partial): verification/path cost at scale** — see benchmark results below. Full E2 (10⁵-object constraint budgets) and E3 (merge conflict detection precision/recall) remain planned; no claims are made for them.

## Benchmark methodology

- Harness: `crates/rahn-state/tests/scaling.rs` (ignored test), run in release mode: `cargo test -p rahn-state --release --test scaling -- --ignored --nocapture`.
- Workload: ring topology (n nodes, n ring links, 1 interface/node); mutation severs the ring's middle third. Deterministic construction (no randomness in workloads).
- Metrics: median wall-clock of 3–5 runs per operation; single process.
- Environment: Windows 11 (build 28000), 12th Gen Intel Core i5-12450HX, 12 GB RAM, rustc 1.99.0-nightly (2026-07-19), commit `36dd2de`, `--release`.

## Benchmark results (medians, milliseconds)

| nodes | build | serialize | hash | diff | verify | path |
|---:|---:|---:|---:|---:|---:|---:|
| 10 | 0.014 | 0.002 | 0.002 | 0.006 | 0.008 | 0.007 |
| 100 | 0.469 | 0.006 | 0.011 | 0.079 | 0.078 | 0.091 |
| 1 000 | 3.758 | 0.046 | 0.092 | 0.588 | 0.620 | 0.809 |
| 10 000 | 23.780 | 1.143 | 1.346 | 7.387 | 9.504 | 9.992 |
| 100 000 | 268.995 | 12.820 | 17.384 | 85.959 | 103.204 | 125.914 |

Interpretation (scoped to this single-machine run):

- Serialization and hashing scale near-linearly; 100k-node states serialize in ~13 ms and hash in ~17 ms — identity checking at every commit is viable at these scales.
- Verification (4 structural invariants over 100k links) ~103 ms — acceptable for commit-time gating at 100k-object scale; per-node connectivity requirements would add path-query cost each.
- Shortest path on a 100k-node ring (~50k hops worst case) ~126 ms — BFS is linear; real topologies are far shallower.
- All timings grow roughly linearly in n across the measured decade — no pathological blowup observed.

## Bugs found and fixed during the stage

1. **Merge dropped added nodes' interfaces** — `side_changes` treated an added node's interfaces as implicit; link application then failed (or would have produced interface-less nodes). Found by the diverged-merge end-to-end test; fixed and covered.
2. **Diff omitted added/removed nodes' interfaces** — diff-derived operations could not reconstruct the state. Fixed: full state delta reported; plan generation subsumes interface removals into node removals.

## Limitations

- No addressing yet (interfaces have free-form metadata; typed address fields are the natural next format addition — deferred to keep format v2 scoped).
- Per-op transition application clones the network: batch application of m operations costs O(m·n). Acceptable at measured scales (see results) but recorded as the first real performance debt of the transition model; a copy-on-write or batched-apply design would need its own ADR.
- Merge conflict detection remains object-level (no constraint-level infeasibility analysis — Stage 2 roadmap item for the constraint engine, still open).
- Benchmarks are single-machine, single-process medians; no cross-machine reproducibility of timing numbers (identity determinism is cross-platform test-enforced, timings are not).

## Unresolved questions

- E3: merge conflict detection precision/recall on injected conflicts (needs a scenario generator).
- Constitution expressiveness (RQ4): only connectivity-style requirements exist; redundancy/failure-domain requirements need graph concepts (Stage 3+).
- Path explanations: `rahn path` returns the route; *why* (weights/policy) is RQ9-analog work for later stages.

## Next-stage implications

- Stage 3 (isolated Linux execution) can proceed on the interface model: execution plans now name `node/interface` targets, which map naturally to netns+veth pairs.
- The O(m·n) batch-apply cost should be revisited before Stage 4 observation ingestion (high-frequency operations).
