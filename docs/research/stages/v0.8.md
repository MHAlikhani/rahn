# Stage 8 Report — v0.8.0-alpha: Network CI / Verification

Date: 2026-08-15. ADR: [0017](../../adr/0017-ci-verification.md). Release: **v0.8.0-alpha**.

## Objective

Make network changes testable before deployment: a machine-facing verification surface that any CI system can gate on (charter Stage 8), without dashboards or servers.

## Research motivation and architecture decision

Every RAHN commit is already constitution-gated; Stage 8's question was purely about the *interface* to CI systems. ADR 0017 fixes the contract: `rahn test [ref]` emits a deterministic TSV report (per-invariant `PASS|FAIL`, evidence, summary) and uses exit codes (0/1/2) as the machine contract — pipelines branch on exit codes alone. Invariant identifiers (e.g. `named-connectivity:a:b`) are a stable machine contract; renaming one requires an ADR. No wall clock, no environment data, no tty dependence: identical repository state produces identical report bytes (test-enforced).

## Implementation changes

- `rahn test [ref]` — verification of a committed state (default HEAD; ref = branch or commit id) against the structural invariant floor plus the constitution; working-state verification remains `rahn verify`.
- `examples/network-ci.yml` — copy-paste GitHub Actions gate (build + `rahn test` on `.rahn/**` changes).
- No new concepts beyond the report format; verification semantics are unchanged from ADR 0006.

## What CI catches today

Topology validity (referential integrity, endpoints, duplicate links, self-loops), named connectivity requirements, and isolation (`prohibit-connectivity`) violations — i.e., at least one meaningful class of invalid network states is rejected before execution, satisfying the Stage 8 gate. Latency/failure-domain classes await addressing (Stage 2-scope deferral).

## Tests

- E2E: pass semantics on empty and committed states; per-ref (commit id) testing; **output determinism** (identical bytes across invocations); constitution-driven failure with `FAIL` evidence lines and exit-1 semantics; unknown-ref rejection.
- Workspace: 130 tests green; fmt and clippy (`-D warnings`) clean.

## Limitations

- Committed states only for `rahn test` (working-state flow is `rahn verify`); no multi-state batch mode yet.
- Reachability/latency/failure-domain checks wait on addressing; the report schema already accommodates them (invariant ids).
- The example workflow is documentation, not an active pipeline in this repository.
- No benchmark: verification cost was already measured at scale in Stage 2 (E2 partial, ~103 ms at 100k links); nothing new to measure.
