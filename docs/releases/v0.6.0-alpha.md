# RAHN v0.6.0-alpha — Distributed State

*Pre-release · tag `v0.6.0-alpha` · commit `a6ce4f7` (this line is finalized at publication).*

## Overview

Stage 6 makes RAHN capable of safely representing and synchronizing network state across multiple RAHN instances — as a defensible distributed-state model, not "clustering". Per the requirements study (RQ7, ADR-0015), RAHN's writes are low-frequency, human-scale, and merge-aware; the chosen model is **peer synchronization over content-addressed history**, not leader consensus.

## Highlights

- **Per-replica authority:** every replica is authoritative for its own committed history; sync exchanges only immutable, hash-verified records (branch-tip offers + fetched commits/states with complete ancestries).
- **Deterministic convergence:** divergent branch tips converge exclusively through the fail-closed semantic merge (ADR 0007), producing **byte-identical merge commits on every replica** (parents ordered lexicographically by commit id, message `sync merge`, constitution-checked).
- **Fail-closed divergence:** merge conflicts and constitution rejections leave divergent tips in place with explainable reports; repeated syncs reproduce the conflict; nothing is auto-resolved.
- **Partition behavior:** local writes remain available during partition; divergence is represented, not prevented; recovery is reopen + fetch-by-hash, with partial recovery as a normal outcome.
- **Idempotent sync:** duplicated, reordered, and reversed message exchange converges to the same state (test-enforced).

## Implemented

- `rahn-dist` crate: deterministic two-way sync engine (`offer`, fetch, adoption, merge convergence, per-branch outcomes: `UpToDate | Fetched | Merged(id) | Conflict`).
- Seven failure-scenario test suites: adoption both directions, disjoint convergence, fail-closed conflict persistence, restart recovery, corrupted-data refusal, idempotency.
- Sync benchmark harness with recorded methodology.

## Measured (single machine, medians; see docs/research/stages/v0.6.md)

Replicating a 10 000-commit history between fresh repositories costs ~80.9 s (~3–8 ms/object — per-object file operations plus double hashing; transport-shaped, not algorithm-shaped). `offer` is sub-millisecond at all scales.

## Explicit non-claims

- **No linearizability, serializability, or cross-replica strong consistency.** Per-replica read-your-writes and monotonic history are the only read guarantees.
- **No consensus/leader election, no epochs** (deliberate non-concepts — ADR 0015).
- **No authentication:** replica identity is self-asserted (documented trust boundary); integrity via content hashes; replay is idempotent. Signed transitions remain Future.

## Known limitations

- Sync transport is per-object (~3–8 ms/object) — packing/batched transfer is a Stage 7 follow-up (own ADR).
- Observations and causal logs are per-replica local; log replication is Future.
- Diverged constitution files across replicas are not yet detected as a first-class conflict.
- No CLI command for sync in v0.6 (library prototype); proposed for Stage 7.
- Alpha-grade software; not for production networks.
